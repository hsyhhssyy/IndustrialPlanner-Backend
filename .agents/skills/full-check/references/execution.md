# 后端完整检查执行规范

## 检查范围

除非用户明确指定某个 Worker、测试文件或测试集并要求单项执行，否则所有“运行测试”“检查代码”“验证改动”请求都执行完整检查，不得自行缩小范围。明确指定单项时改用 `test-writing` Skill。

## 前置检查

1. 在仓库根目录执行命令。
2. 读取根 `package.json`，确认脚本仍为当前真相；脚本变化时以当前文件为准并在报告中说明。
3. 检查 `git status --short`，只用于记录工作区状态，不修改或清理文件。
4. 不读取或连接 `.dev.vars`、`.temp/deploy-config.json` 或 Cloudflare 远程资源。

## 固定顺序

每项单独执行，不使用 `&&` 串联。某项失败后记录退出码和关键错误，继续执行下一项。

### 1. Lint

```bash
pnpm lint
```

### 2. TypeScript

```bash
pnpm typecheck
```

### 3. 全量测试

```bash
pnpm test
```

`pnpm test` 通过 workspace 递归执行所有已声明测试脚本。不得自行替换为某个包的 `vitest run` 后宣称全量通过。

## 长任务

- 命令以前台方式启动。
- 工具返回会话句柄时续接同一个进程，直到取得最终退出状态。
- 不使用后台进程、`nohup`、`setsid` 或另开终端轮询。
- 单次等待不超过 60 秒；未结束时继续续接。

## 结果处理

- 只执行检查，不根据结果修改业务代码、测试、配置、migration 或锁文件。
- 不为了修绿而安装依赖、连接远程资源或改变环境。
- 只摘录关键失败信息，不粘贴完整长日志。
- 若某 package 没有对应脚本，由 pnpm 当前递归行为决定；不得伪造该 package 已被该项覆盖。
- Miniflare 或原生模块不可用时，记录环境失败和未验证边界。
- 本仓库没有统一 build 脚本；不得虚构 build 检查。需要 Wrangler 构建或 dry-run 时必须由用户明确提出，并单独说明范围。
