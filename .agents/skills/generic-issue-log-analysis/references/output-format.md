# 后端 Issue 分析输出格式

## Issue 概要

- Issue：编号与链接。
- 版本 / tag / commit / 环境。
- Worker / API / 请求 ID。
- 用户现象与复现条件。

## 证据概览

- 实际读取的公开材料。
- 缺失或与复现不匹配的关键证据。

## 关键时间线

按客户端、Gateway、目标 Worker、D1/R2/KV/Service Binding 和响应顺序列出关键事件。

## 根因判断

- 已证实根因。
- 高概率怀疑点。
- 当前主线是否仍存在同类风险。
- 证据之间的冲突。

## 建议

1. 最小且结构正确的修复方向。
2. 需要补充的测试、日志、trace 或存储证据。
3. 可用的临时缓解及其风险；没有安全 workaround 时明确说明。

## 置信度

- 高 / 中 / 低。
- 提升置信度所需的最低成本证据。

只要求分析时，建议必须停留在方案层，不附带未授权实现。
