# 后端提交执行规范

## 授权边界

`commit-all.sh` 会：

1. 递归处理 `.docs` submodule。
2. 对每个有改动的仓库执行 `git add .` 和 commit。
3. 对配置了 upstream 且存在未推送提交的仓库自动 push。
4. 最后提交并可能推送根仓库。

因此，只有用户明确授权这一完整影响范围时才能执行。用户只说“本地提交”“不要推送”或授权范围不清楚时，停止并说明项目脚本会自动推送；不得改用 `git commit` 绕过脚本。

## 执行前检查

分别执行只读检查：

```bash
git status --short
```

```bash
git diff --stat
```

```bash
git -C .docs status --short
```

```bash
git -C .docs diff --stat
```

确认：

- 根仓库和文档 submodule 的全部改动都属于用户授权范围。
- 不包含 secret、`.dev.vars`、部署配置、日志或临时文件。
- 没有其他协作者的无关改动。
- 需要的检查已经完成；若未完成，在提交前明确告知。

## 提交信息

使用简洁中文，建议不超过 72 字符：

- `feat:`：用户可感知的新能力或 API 行为。
- `fix:`：修复已有终端现象。
- `dev:`：AI 规则、文档、CI、构建、依赖、目录和纯内部重构。

`fix:` 描述用户或调用方看到的现象，不用 SQL、D1、CAS 或内部函数名代替。

一次提交存在多个独立改动时，提交信息必须覆盖实际范围；无法用一条短标题准确表达时先收敛提交范围，不得遗漏。

## 唯一允许的提交方式

```bash
./commit-all.sh <提交信息>
```

禁止直接执行 `git commit`，也禁止修改脚本、调用底层 Git 命令或使用其他工具绕过。

## 完成后

再次检查根仓库和 `.docs` 状态，报告：

- 每个实际创建的 commit 及所属仓库。
- 哪些仓库已推送，哪些因无 upstream 或推送失败而只保存在本地。
- 是否仍有未提交改动。
