# 后端项目文档写作

## 能做什么

- 按 [通用写作标准](references/writing-standard.md) 维护可脱离对话独立成立的长期文档。
- 编写 Stage、需求或 Bug 文档时同时读取 [专项文档要求](references/document-types.md)。

## 不能做什么

- 不得依赖聊天上下文、只写结论不写原因，或混淆用户要求、阶段约束、客观事实与实现者决策。
- 不得让归档架构或已失效方案继续作为当前真相，也不得忽略 `.docs` 的独立 submodule 边界。
